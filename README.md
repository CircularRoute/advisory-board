# Advisory Board

A deliberation engine. You give it a hard question; the strongest model from each
major AI provider answers **independently**, the members **blind-review** each other
with identities stripped, and a non-member **Chairman** synthesises one final answer
that names where they disagreed.

**Its purpose is to surface disagreement, not manufacture consensus.**
Advisory only — it answers a human; it never decides, acts, or writes to any other system.

## The mechanism

1. **Independent opinions** — the question goes to every board member in parallel; no member sees another's answer.
2. **Blind peer review** — each member gets the *other* members' answers, identities stripped, order shuffled per reviewer, and must evaluate each response before producing a machine-parseable `FINAL RANKING:` block. Unparseable rankings are reported, never silently dropped.
3. **Chairman synthesis** — a **non-member** Chairman receives the question, answers, and reviews — *anonymised for the Chairman too* — and writes the final answer with explicit sections: where the board agreed, where it split (with the strongest minority view), and what would resolve it. Identities are revealed only afterwards, in the report.

Failure policy: a member that errors or times out is dropped and the board sits
short-handed (stated loudly in the output). If all members fail, you get an error,
never a synthesised answer from nothing.

## Board tiers

| Tier | OpenAI | Anthropic | Google (opt-in) | Default chairman |
|---|---|---|---|---|
| top | gpt-5.6-sol | claude-fable-5 | gemini-3.1-pro-preview | claude-opus-5 |
| mid *(default)* | gpt-5.6-terra | claude-opus-5 | gemini-3.6-flash | claude-fable-5 |
| low | gpt-5.6-luna | claude-sonnet-5 | gemini-3.5-flash-lite | claude-opus-5 |

All model IDs verified against the providers' `/models` endpoints on 2026-08-05.
Google is **off by default** (prepaid credit exists for Anthropic and OpenAI only);
enable with `--providers=anthropic,openai,google`. The chairman is always a
non-member by default. Edit tiers in one place: [src/config.js](src/config.js).
Gemini prices in the config are estimates (marked as such in cost output).

## Setup

```bash
npm install
export ANTHROPIC_API_KEY=... OPENAI_API_KEY=...   # and GEMINI_API_KEY for google
```

Keys load from environment variables at runtime — never hardcoded, committed, or
printed. Alternatively point at a .env-style file: `--env-file=path` or `AB_ENV_FILE=path`.

## Phase 1 — CLI

```bash
node src/cli.js "Should we build X or buy Y?"                 # mid tier, anthropic+openai
node src/cli.js "…" --tier=top
node src/cli.js "…" --providers=anthropic,openai,google
node src/cli.js "…" --chairman=gpt-5.6-sol
node src/cli.js "…" --compare=mid,low                          # tier comparison mode
node src/cli.js --leaderboard                                  # aggregate leaderboard
```

Every run prints **tier and cost at the top**, split by provider, and persists an
inspectable record (each member's verbatim response, every review + ranking + the
de-anonymised mapping, leaderboard, per-call costs) to `sittings/<timestamp>-<slug>/`.
Run titles are generated by the cheapest model and billed to a separate
`housekeeping` cost line.

**Tier comparison mode** (`--compare=mid,low`) runs the same question at each tier
and reports side by side: each tier's final answer, whether the tiers actually
reached different conclusions, and each tier's cost — i.e. where does the expensive
board change the answer versus merely cost more?

**Aggregate leaderboard**: each reviewer's ranking becomes positions; positions are
averaged per model across reviewers and accumulated in `leaderboard.json` across all
sittings — over time, which provider is actually strongest on the questions *you*
ask. With only two members it is labeled low-confidence (each reviewer ranks a
single response, so positions are degenerate).

## Phase 2 — HTTP service + web page

```bash
export ADVISORY_BOARD_KEY=$(openssl rand -hex 24)   # required; server refuses to start without it
npm start                                            # listens on :8787
```

- `POST /ask` `{question, tier?, providers?, chairman?}` → full sitting record (Bearer auth)
- `GET /leaderboard` → aggregate leaderboard (Bearer auth)
- `GET /` → minimal web page: text box, tier selector, provider checkboxes, answer
- `GET /healthz` → public health check

### Deploy (Render)

**`render.yaml` now deploys the ported board console (`advisory-board/`), not this
`src/` service** — see [advisory-board/README.md](advisory-board/README.md) for the
hosted console (key-protected via `BOARD_ACCESS_KEY`, runs on a persistent disk).
The `src/` service here can still be run manually (`ADVISORY_BOARD_KEY=... npm start`)
if you want the REST + MCP surface.

## Phase 3 — Remote MCP server

The same service exposes the engine as a remote MCP server at `/mcp`
(Streamable HTTP, stateless) with one tool:

```
ask_advisory_board(question, tier?, providers?)
  -> { final_answer, agreements, disagreements, what_would_resolve_it,
       leaderboard, cost, board, chairman, notes }
```

Connect it in Claude's connector settings (desktop or mobile) with URL
`https://<your-host>/mcp?key=<ADVISORY_BOARD_KEY>` — the query-param form exists
because some MCP clients cannot send custom headers; `Authorization: Bearer` also
works. Then, in any Claude conversation: *"ask the advisory board whether X."*
A run takes several minutes; the tool reports cost in its result.

## Hard rules (enforced in code)

- Advisory only; never acts on any other system.
- Never hide disagreement — the Chairman must name splits and the strongest minority view.
- The Chairman reconciles, never invents; anonymisation is mandatory in peer review **and** for the Chairman.
- Fail loudly, never fabricate — short-handed boards are flagged; all-fail returns an error.
- Cost is real: logged per call, split by provider, printed at the top of every output.
- Keys from env only; the hosted service requires `ADVISORY_BOARD_KEY`.

One deliberate deviation: Anthropic's optional server-side refusal fallbacks are
**not** enabled — a silent model substitution would corrupt the board's identity
guarantees, so a refusal is surfaced as a member failure instead.
